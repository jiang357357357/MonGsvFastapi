# 快速启动

> 本文档帮助你在 5 分钟内跑起 MonGSV 后端服务。

## 前置条件

- Python 3.10
- 虚拟环境已创建并激活（`.venv/`）
- 依赖已安装：`uv sync` 或 `pip install -r requirements.txt`
- Nvidia GPU（推荐，半精度推理）或 CPU

## 启动方式

### 方式一：通过入口脚本启动（推荐）

自动检测端口冲突，执行清理后启动：

```bash
cd Code/FastApi/Main
python run_gateway.py
```

### 方式二：直接启动网关

```bash
python -m Code.FastApi.Base.Gateway.run_unified_gateway --host 0.0.0.0 --port 40302
```

### 方式三：开发模式启动（前后端一起）

```bash
python Code/Main/launch_dev.py --no-frontend
```

## 验证启动

服务启动后，访问以下地址确认：

| 地址 | 说明 |
|------|------|
| `http://localhost:40302/` | 服务根路径，返回服务信息 |
| `http://localhost:40302/health` | 健康检查，列出所有子服务状态 |
| `http://localhost:40302/docs` | Swagger API 文档（可在线测试） |
| `http://localhost:40302/redoc` | Redoc 风格 API 文档 |
| `ws://localhost:40302/ws/asr/transcribe` | 实时 ASR WebSocket；连接成功会返回 `2-pass 流式识别已就绪` |
| `ws://localhost:40302/ws/tts/stream` | 流式 TTS WebSocket；支持 LLM delta 输入并返回 PCM 音频块 |

健康检查正常时的返回示例：

```json
{
  "gateway_status": "healthy",
  "services": {
    "audio_slice": { "status": "available" },
    "asr_recognition": { "status": "available" },
    "text_processing": { "status": "available" },
    "audio_features": { "status": "available" },
    "semantic_encoding": { "status": "available" },
    "gpt_training": { "status": "available" },
    "sovits_training": { "status": "available" },
    "inference": { "status": "available" }
  },
  "total_services": 8,
  "healthy_services": 8
}
```

实时 ASR 握手若返回 `403 Forbidden`，优先确认后端已拉取最新代码并重启。当前版本的 WebSocket 路由不做 token 鉴权、不限制 Origin；正确日志应显示 `"WebSocket /ws/asr/transcribe" [accepted]`。

## 端口配置

端口优先级：**命令行参数 > `.monconfig` 配置 > 默认值**

### 方式 A：命令行参数

```bash
python run_gateway.py --port 8080 --host 0.0.0.0
```

完整参数列表：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--host` | 绑定地址 | `0.0.0.0` |
| `--port` | 监听端口 | `40302` |
| `--workers` | 工作进程数 | `1` |
| `--reload` | 自动重载（开发用） | `false` |
| `--log-level` | 日志级别 | `info` |
| `--enable-auth` | 启用 API 认证 | `false` |
| `--api-key` | API 密钥 | `None` |
| `--max-concurrent` | 最大并发任务数 | `10` |

### 方式 B：修改 `.monconfig`

编辑项目根目录下的 `.monconfig` 文件：

```ini
[server]
HOST=0.0.0.0
PORT=40302
RELOAD=false

[log]
LEVEL=info

[gpu]
ENABLED=true
DEVICE=cuda
HALF_PRECISION=true
```

## 命令行工具

```bash
# 查看端口占用状态
python run_gateway.py status

# 停止占用端口的进程
python run_gateway.py stop

# 停止进程并清理临时目录
python run_gateway.py cleanup
```

## 常见问题

### 端口被占用

启动时自动检测并提示，可手动执行 `python run_gateway.py stop` 清理。

### 服务加载失败

健康检查中对应服务状态为 `load_error`，可通过 `/services/reload/{name}` 热重载：

```bash
curl -X POST "http://localhost:40302/services/reload/inference"
```

### 认证启用

```bash
python run_gateway.py --enable-auth --api-key my-secret-key
```

启用后所有请求需携带 Header：

```http
Authorization: Bearer my-secret-key
```

## 快速验证 TTS

### 推荐方式：按角色 + 情感合成

前端和 music 后端对接时，推荐调用业务接口。调用方只需要传世界、版本、角色、情感和文本；后端会自动查找模型路径、参考音频和参考文本，并自动加载 GPT/SoVITS 模型。

```bash
curl -X POST "http://localhost:40302/api/synthesis/role-emotion" \
  -H "Content-Type: application/json" \
  -d '{
    "world_id": 1,
    "version": "v2Pro",
    "role_id": 1,
    "emotion": "温柔",
    "text": "你好，欢迎使用语音合成系统。",
    "text_language": "zh",
    "speed": 1.0,
    "how_to_cut": "凑四句一切"
  }' \
  -o response.json
```

### 高级方式：直接调用底层推理接口

底层 `/inference/tts` 不会根据角色或情感自动查参考音频。调用方必须先加载模型，并显式传 `ref_audio` 或 `ref_audio_path`。

```bash
# 1. 加载模型
curl -X POST "http://localhost:40302/inference/models/load" \
  -F "gpt_path=GPT_weights_v2Pro/my_model.ckpt" \
  -F "sovits_path=SoVITS_weights_v2Pro/my_model.pth"

# 2. 语音合成
curl -X POST "http://localhost:40302/inference/tts" \
  -F "text=你好，欢迎使用语音合成系统。" \
  -F "text_language=zh" \
  -F "ref_audio_path=/path/to/ref.wav" \
  -F "prompt_text=参考音频文字内容" \
  -F "return_base64=true" \
  -o response.json
```
