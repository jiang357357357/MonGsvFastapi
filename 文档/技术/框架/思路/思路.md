# GPT-SoVITS srcManager 框架重构方案 (FastAPI -> Django)

本文档旨在梳理将 `srcManager` 整体转换为 Django 框架形态的重构思路、架构映射及实施步骤。

---

## 1. 核心重构目标

将 `srcManager` 从一个被 FastAPI 驱动的子模块，转换为一个**自持的、异步的 Django 项目**。

- **框架转换**: FastAPI/Starlette → Django (ASGI)。
- **无感迁移**: 保持所有对外 API 路径（`/Core/api/...`）和返回 JSON 结构完全不变。
- **服务集成**: 统一管理 WebFront、Manager 静态页面及 Resources 资源分发。
- **逻辑复用**: 100% 复用 `inference`, `train`, `preprocess` 等核心业务逻辑。

---

## 2. 目标架构设计

重构后的项目将以 `srcManager` 为 Django 项目包，目录结构如下：

```text
GSV/ (项目根目录)
├── manage.py                # 移动至此：项目管理总入口
├── srcManager/              # 核心包：转换为 Django Project 形式
│   ├── settings.py          # 新增：Django 全局配置
│   ├── urls.py              # 新增：总路由分发 (含 API, Front, Manager)
│   ├── asgi.py              # 新增：ASGI 入口 (替代 GptSovMain.py 的容器功能)
│   ├── config/              # 业务配置 (AppConfig)
│   ├── routes/              # 转换为 Django View 层
│   ├── inference/           # 业务逻辑：推理模块 (保持不动)
│   ├── preprocess/          # 业务逻辑：预处理模块 (保持不动)
│   ├── train/               # 业务逻辑：训练模块 (保持不动)
│   ├── util/                # 工具类 (日志、扫描器等)
│   └── ...
├── code/
│   ├── WebFront/            # 静态资源：Web 前端
│   └── ...
└── resources/               # 静态资源：音频/模型资源文件
```

## 3. 关键组件映射

| 功能模块 | 现有实现 (FastAPI) | Django 映射方案 |
| :--- | :--- | :--- |
| **容器入口** | `GptSovMain.py` / `uvicorn.run` | `srcManager/asgi.py` / `uvicorn` |
| **服务分发** | `port_mount/server.py` (mount 逻辑) | `srcManager/urls.py` (path 映射) |
| **API 路由** | `routes/api/*.py` (APIRouter) | `srcManager/routes/api/views_*.py` (Async View) |
| **业务配置** | `config/app_config.py` (AppConfig) | `settings.py` 引入并配合 `AppConfig` |
| **静态挂载** | `StaticFiles(directory=...)` | `django.views.static.serve` 或 ASGI 路由 |
| **多语言初始化** | `GptSovMain.py` 启动脚本 | `srcManager/__init__.py` 或 `AppConfig.ready()` |

## 4. 详细迁移逻辑

### 4.1 入口与路由 (The "Outer Shell")
- **URL 保持**: 在 `srcManager/urls.py` 中，使用 `path('Core/api/...', ...)` 显式复刻现有路径。
- **静态集成**: 
    - `/Front` 路径通过视图读取并返回 `WebFront/index.html`。
    - `/resources` 路径映射到 `resources/` 目录的文件服务视图。
- **异步支持**: 所有的 View 必须定义为 `async def`，以支持长耗时的推理和训练任务。

### 4.2 视图适配 (The "Adapter")
将 `routes/api/` 下的函数签名从 FastAPI 风格转换为 Django 风格：
- **参数获取**: `Query(...)` → `request.GET.get()`；`Body(...)` → `json.loads(request.body)`。
- **返回结构**: 使用 `JsonResponse` 封装数据，确保 `success`, `message`, `data` 键值对与原 API 一致。
- **异常处理**: 编写 Django 中间件 (Middleware) 捕获业务异常，统一返回原有的 422/500 格式。

### 4.3 配置融合
- Django 的 `settings.py` 负责框架级配置（ALLOWED_HOSTS, INSTALLED_APPS）。
- 现有的 `srcManager/config/app_config.py` 继续负责业务级配置（路径检测、端口定义）。
- 在 `settings.py` 中实例化 `AppConfig` 并挂载到 `django.conf.settings`。

---

## 5. 迁移路线图

1.  **初始化骨架**:
    - 在 `srcManager` 内创建 `settings.py`, `urls.py`, `asgi.py`。
    - 将 `manage.py` 放置到根目录并配置 `DJANGO_SETTINGS_MODULE`。
2.  **Pilot 试点**:
    - 迁移 `info_routes.py` (只读接口)。
    - 验证 `/Core/api/info/versions` 在 Django 下的返回结果。
3.  **核心迁移**:
    - 逐一改写 `inference`, `train`, `preprocess` 的路由为 Django Views。
    - 在 `urls.py` 中配置静态文件分发逻辑。
4.  **环境适配**:
    - 将 `GptSovMain.py` 中的 GPU 检测、DLL 加载等初始化代码迁移至 Django 的启动生命周期中。
5.  **回归验证**:
    - 运行 `srcManager/tests` 脚本，确保所有自动化测试在 Django 环境下通过。

---

**设计哲学**: 
本次重构的核心是**“结构格式化”**。我们不是在重写业务，而是给业务穿上一套 Django 的衣服，使其能够利用 Django 的管理后台 (Admin)、身份验证和中间件生态，同时保留原有的高性能异步能力。
